## 1. Summary
This feature stands up the backend foundation: a runnable FastAPI app wired to PostgreSQL via SQLAlchemy 2.x, settings loaded from the environment with `pydantic-settings`, Alembic ready for migrations, a `GET /api/v1/health` endpoint that confirms DB connectivity, and a pytest harness with an isolated test database. After this ships there is no owner-visible behaviour yet — it is the skeleton every subsequent feature hangs off.

## 2. User stories
- As the developer, I want a running FastAPI app connected to Postgres so that I can build features on a known-good foundation.
- As the developer, I want `alembic upgrade head` to run on an empty DB so that schema changes in later features apply cleanly.
- As the developer, I want a health endpoint that checks the DB so that I (and later the mobile Settings screen in F0.2) can tell whether the backend is reachable and its database is up.
- As the developer, I want a pytest harness with a separate test database so that tests never touch dev data and every later feature can add tests the same way.

## 3. Scope
**In scope:**
- Backend directory layout from `CLAUDE.md` §6, `pyproject.toml` (deps + dev deps), `ruff` config, `.python-version` pinning 3.12.
- **No Docker.** Local dev/test use the machine's system **PostgreSQL 18** on `localhost:5432`. Databases `pgrent_dev` / `pgrent_test`, role `pgrent` (the name avoids Postgres's reserved `pg_` prefix). (Decided with the developer, 2026-10-20.)
- `backend/.env.example` with `DATABASE_URL`, `TEST_DATABASE_URL`, `JWT_SECRET`, `TZ=Asia/Kolkata`.
- `app/core/config.py` — `Settings` via `pydantic-settings`.
- `app/db/` — SQLAlchemy 2.x engine, session factory, declarative `Base`, a `get_db` dependency.
- Alembic initialised (`alembic.ini`, `alembic/env.py` wired to `Base.metadata` and `Settings`), with an **empty baseline migration** so `alembic upgrade head` succeeds on an empty DB.
- `app/main.py` — app factory with `/api/v1` router registration.
- `app/api/routes/health.py` — `GET /api/v1/health` returning `{"status": "ok"}` after a DB connectivity check.
- `tests/conftest.py` — test DB engine, create/drop tables per session, `db` and `client` fixtures.
- One test: health endpoint returns 200 and the expected body.

**Out of scope (do NOT build now):**
- Any domain models (`owners`, `pgs`, `rooms`, `tenants`, etc.) — those arrive with their own features. The skeleton ships with **zero tables**.
- Auth, JWT, password hashing (F1).
- APScheduler / jobs (F7) — create the `app/jobs/` folder only if trivially empty; otherwise defer.
- Any mobile work (F0.2).
- Deployment/hosting config (Render/Neon) beyond `.env.example` documenting the vars.

## 5. Data model changes
**None.** The skeleton creates no tables. The baseline Alembic migration is intentionally empty (no `op.*` calls) so that `alembic upgrade head` on an empty DB produces only the `alembic_version` bookkeeping table. Later features each add their own migration.

Migration to add: `alembic/versions/<rev>_baseline.py` — empty `upgrade()`/`downgrade()`.

## 6. Business rules
1. **Config via environment only.** No secrets or DB URLs in code. `Settings` reads from env / `.env`; `.env` is gitignored; `.env.example` is committed. (CLAUDE.md §9)
2. **Timezone.** `TZ=Asia/Kolkata` is set in `backend/.env.example`. No date logic exists yet, but the convention is established here. (CLAUDE.md §7)
3. **API prefix.** All routes live under `/api/v1`, JSON only. (CLAUDE.md §8)
4. **Health check must verify DB connectivity**, not just that the process is up: execute a trivial `SELECT 1` through a session. If the DB is unreachable, the endpoint returns a non-200 (see §7).
5. **Error format.** Errors use `{"detail": "..."}` with proper HTTP codes. (CLAUDE.md §8)
6. **Test isolation.** Tests run against `TEST_DATABASE_URL`, a database separate from dev. Tables are created at session start and dropped at the end; the suite never mutates the dev DB. (CLAUDE.md §5)
7. **Idempotent migration baseline.** Running `alembic upgrade head` twice is a no-op after the first. (established convention; critical for F7 later)

## 7. API contract

### `GET /api/v1/health`
- **Auth:** none.
- **Request:** no params, no body.
- **Success response — 200:**
```json
{ "status": "ok" }
```
- **Error case — DB unreachable — 503:**
```json
{ "detail": "database unavailable" }
```
  Implement by catching the exception from the `SELECT 1` and raising `HTTPException(status_code=503, detail="database unavailable")`.
- **PG-scoping:** N/A (no PG concept yet).

> Open question (see §13): FEATURES.md only requires 200-with-DB-up. The 503-on-DB-down path is a recommended addition that makes the F0.2 "Can't reach server" state meaningful. If the reviewer prefers the simplest possible endpoint, it may just return `{"status": "ok"}` and let a connection failure surface as a 500. Recommended default: **return 503 as above.**

## 8. Backend implementation plan
Ordered. All paths under `backend/` unless noted.

1. **`pyproject.toml`** — project metadata; `requires-python = ">=3.12,<3.13"`.
   - deps: `fastapi`, `uvicorn[standard]`, `sqlalchemy>=2`, `alembic`, `pydantic>=2`, `pydantic-settings`, `psycopg[binary]` (psycopg3; confirm driver in URL as `postgresql+psycopg://`).
   - dev deps (`[dependency-groups]` or `[project.optional-dependencies].dev`): `pytest`, `httpx`, `ruff`.
   - `[tool.ruff]` config (line length, target py312).
2. **No `docker-compose.yml`.** The DB is the machine's system PostgreSQL 18. One-time setup (run by the developer as the `postgres` superuser): `CREATE USER pgrent WITH PASSWORD 'pgrent';` + `CREATE DATABASE pgrent_dev OWNER pgrent;` + `CREATE DATABASE pgrent_test OWNER pgrent;`.
3. **`backend/.env.example`** (and a gitignored `backend/.env`) — document:
   ```
   DATABASE_URL=postgresql+psycopg://pgrent:pgrent@localhost:5432/pgrent_dev
   TEST_DATABASE_URL=postgresql+psycopg://pgrent:pgrent@localhost:5432/pgrent_test
   JWT_SECRET=change-me-in-production
   TZ=Asia/Kolkata
   ```
   `.env` / `.env.*` are already in the root `.gitignore`.
4. **`app/__init__.py`**, **`app/core/__init__.py`**, etc. — package markers.
5. **`app/core/config.py`** — `class Settings(BaseSettings)` with `database_url: str`, `test_database_url: str | None`, `jwt_secret: str`, `tz: str = "Asia/Kolkata"`; `model_config = SettingsConfigDict(env_file=".env", extra="ignore")`. Expose `get_settings()` (lru_cache) or a module-level `settings`.
6. **`app/db/base.py`** — `class Base(DeclarativeBase): pass`. (Later models import this.)
7. **`app/db/session.py`** — `engine = create_engine(settings.database_url, ...)`, `SessionLocal = sessionmaker(...)`, and `def get_db() -> Generator[Session]:` yielding a session with proper close in `finally`.
8. **`app/api/routes/health.py`** — `router = APIRouter()`; `@router.get("/health")` taking `db: Session = Depends(get_db)`; runs `db.execute(text("SELECT 1"))`; returns `{"status": "ok"}`; on exception raises 503. Response validated by a `HealthResponse` Pydantic schema in `app/schemas/health.py` (`status: Literal["ok"]`).
9. **`app/schemas/health.py`** — `HealthResponse` model (no raw dicts per CLAUDE.md §8).
10. **`app/main.py`** — `def create_app() -> FastAPI:` builds app, includes `health.router` under `prefix="/api/v1"`. Module-level `app = create_app()` for uvicorn.
11. **Alembic** — `alembic init alembic`; edit `alembic.ini` (`sqlalchemy.url` left blank, set from env), `alembic/env.py` to import `Settings` + `Base.metadata` as `target_metadata` and read the URL from settings. Generate an **empty** baseline: `alembic revision -m "baseline"` (hand-write empty `upgrade`/`downgrade`), NOT `--autogenerate` (nothing to generate).
12. **`tests/conftest.py`** —
    - `engine` against `TEST_DATABASE_URL`.
    - session-scoped fixture: `Base.metadata.create_all(engine)` at start, `drop_all` at end.
    - `db` fixture: a session (optionally per-test transaction rollback).
    - `client` fixture: `TestClient(create_app())` with `app.dependency_overrides[get_db]` pointing at the test session.
13. **`tests/test_health.py`** — the health test (§10).
14. **`backend/README` note or inline** — none required; commands already in CLAUDE.md §11.

Router registration signature: `app.include_router(health.router, prefix="/api/v1", tags=["health"])`.

### Manual checklist (developer)
1. Local PostgreSQL 18 is running on `localhost:5432` (system service, no Docker): `systemctl is-active postgresql`.
2. One-time: create role + DBs as the postgres superuser — `sudo -u postgres psql -c "CREATE USER pgrent WITH PASSWORD 'pgrent';" -c "CREATE DATABASE pgrent_dev OWNER pgrent;" -c "CREATE DATABASE pgrent_test OWNER pgrent;"`.
3. `cd backend && uv sync` → dependencies install under Python 3.12; `.venv/` created.
4. `cp .env.example .env` (first time only).
5. `uv run alembic upgrade head` → runs clean on the empty DB; `alembic_version` table appears, no other tables. Run it **again** → no changes (idempotent).
6. `uv run uvicorn app.main:app --reload` → starts without error.
7. `curl localhost:8000/api/v1/health` → `{"status":"ok"}`, HTTP 200.
8. Stop Postgres (`sudo systemctl stop postgresql`), curl again → 503 `{"detail":"database unavailable"}`; restart with `sudo systemctl start postgresql`.
9. `uv run pytest` → all pass. `uv run ruff check . && uv run ruff format --check .` → clean.

## 12. Edge cases and risks
- **Python version drift:** system Python is 3.14; building/testing against it instead of pinned 3.12 risks dependency incompatibilities. Mitigate by pinning in `pyproject.toml` and using `uv python install 3.12`.
- **psycopg driver string:** SQLAlchemy 2.x with psycopg3 needs `postgresql+psycopg://`, not bare `postgresql://` (that selects psycopg2). Keep the URL consistent in `.env.example`, `env.py`, and tests.
- **Alembic autogenerate on empty metadata:** do not run `--autogenerate` for the baseline; it would produce an empty migration anyway but can misbehave if `env.py` isn't fully wired. Hand-write the empty baseline.
- **Test DB must exist:** `create_all` needs the `pgrent_test` database to already exist; it is created once manually (manual checklist step 2).
- **Health check holding a connection:** ensure `get_db` closes the session so the health check doesn't leak connections under load.
- **TZ handling:** the `TZ` env var is established here but no code reads it yet; date logic in later features uses `Asia/Kolkata` explicitly.
