## 1. Summary
This feature turns the stock Expo scaffold in `mobile/` into the app shell every later screen hangs off: four bottom tabs (Dashboard, Tenants, Rooms, Settings) as placeholders, an API client that reads `EXPO_PUBLIC_API_URL`, a TanStack Query provider, and a Settings screen that pings the backend's health endpoint and shows **Connected** / **Can't reach server**. Jest is configured with one render test so the test harness is proven. After this ships there is still no rent/tenant behaviour — it is the mobile counterpart of F0.1's skeleton, and the first thing the developer can actually open on their phone over LAN.

## 2. User stories
- As the PG owner, I want to open the app on my phone and see the main sections (Dashboard, Tenants, Rooms, Settings) so that the app feels real even before features land.
- As the PG owner, I want Settings to tell me whether the app is talking to the server so that when something is broken I know it's the connection, not me.
- As the developer, I want an API client that reads one env var (`EXPO_PUBLIC_API_URL`) and a TanStack Query provider so that every later feature fetches data the same way.
- As the developer, I want Jest running with one passing render test so that later features can add component/logic tests on a known-good harness.

## 3. Scope
**In scope:**
- Convert the existing scaffold's two demo tabs (`index` = "Welcome to Expo", `explore`) into **four placeholder tabs**: Dashboard, Tenants, Rooms, Settings (CLAUDE.md §6 tab set).
- `EXPO_PUBLIC_API_URL` wiring: `mobile/.env.example` + a small config helper; API client (`src/api/client.ts`) that builds `${API_URL}/api/v1/...` requests.
- TanStack Query (`@tanstack/react-query` v5): `QueryClientProvider` added in `src/app/_layout.tsx`.
- `useHealth()` query hook hitting `GET /api/v1/health`, with a request timeout so "Can't reach server" shows promptly.
- **Settings screen** renders the connection state across four states: **Checking…** (in flight), **Connected** (200 `{"status":"ok"}`), **Server up, database down** (503), or **Can't reach server** (network error / timeout / other non-2xx), with a manual "Retry" and the resolved API URL shown for debugging.
- Jest configured (`jest-expo` preset + `@testing-library/react-native`), `npm test` script, and **one trivial render test**.
- A small pure helper (`interpretHealth`) that maps a query result → display state, unit-tested.
- **`expo-secure-store` is NOT added here** — deferred to F1 (resolved §12); it is only needed once auth exists.

**Out of scope (do NOT build now):**
- Login / Signup screens, the `(auth)` route group, token storage, `get_current_owner` wiring — all **F1**.
- Any real Dashboard / Tenants / Rooms content, lists, forms, or data fetching beyond the health ping — their own features (F3–F13). Tabs are **placeholders only**.
- `react-hook-form` / `zod` (arrive with the first form, F4).
- PG details editing in Settings (F2); Settings here shows only the health status (+ app/env info).
- Auth headers / `Authorization: Bearer` on the client (F1).
- CI, EAS build config, app store assets, deep-link/`tel:`/`wa.me` helpers (F11/F12).

## 6. Business rules
1. **API base URL comes only from `EXPO_PUBLIC_API_URL`** (an `EXPO_PUBLIC_*` var so Expo inlines it into the client bundle). The client reads it once via a helper; no hard-coded hosts. On a real phone this must be the laptop's LAN IP, not `localhost` (CLAUDE.md §11).
2. **All backend calls target the `/api/v1` prefix** and send/receive JSON (CLAUDE.md §8). The client joins base + path safely (no double slashes).
3. **Health → connection state mapping** (drives the Settings AC):
   - request in flight → **Checking…**
   - HTTP 200 with body `{"status":"ok"}` → **Connected**
   - HTTP **503** (`{"detail":"database unavailable"}`) → **Server up, database down** (distinct state; the client surfaces the status code via `ApiError`)
   - network error, DNS failure, **timeout**, or any other non-2xx → **Can't reach server**
4. **Health request must time out** (recommend ~5 s via `AbortController`) so "Can't reach server" appears promptly instead of hanging — `fetch` has no default timeout.
5. **No secrets in the mobile repo.** `EXPO_PUBLIC_*` values are bundled into the client and are therefore **not** secret; `mobile/.env.example` is committed, `mobile/.env` is gitignored (CLAUDE.md §9). Add `.env` to `mobile/.gitignore` (currently only `.env*.local` is ignored).
6. **TypeScript strict** stays on; no `any` in new code; no business logic in screens — mapping/fetch logic lives in `src/lib` / `src/api` (CLAUDE.md §9).
7. **Big tap targets, clear status colour** (CLAUDE.md §9): the Settings status uses green = connected, red = can't reach (grey while checking). Define these as theme tokens now so later features reuse them.
8. **Timezone / money rules** — none apply yet (no dates or money on screen in F0.2); the conventions are established for later features.

## 7. API contract
This feature **consumes** one existing backend endpoint and defines **no new** ones.

### `GET /api/v1/health` (consumed; defined in F0.1)
- **Auth:** none.
- **Request:** no params, no body. Client sends it to `${EXPO_PUBLIC_API_URL}/api/v1/health` with a ~5 s timeout.
- **Success — 200:**
```json
{ "status": "ok" }
```
  → Settings shows **Connected**.
- **DB down — 503:**
```json
{ "detail": "database unavailable" }
```
  → Settings shows **Server up, database down** (the client's `ApiError` carries `status === 503`; see §6 rule 3).
- **Unreachable:** connection refused / DNS / timeout (backend stopped, wrong LAN IP) → no HTTP response → **Can't reach server**.
- **PG-scoping:** N/A (no PG/owner concept on the client yet).

## 9. Mobile implementation plan
All paths under `mobile/`. Order:

1. **Dependencies** (`package.json`):
   - deps: `@tanstack/react-query` (v5.x). (`expo-secure-store` is **not** added here — deferred to F1, §12.)
   - devDeps: `jest`, `jest-expo`, `@testing-library/react-native`, `@types/jest` (and `react-test-renderer` only if `jest-expo` for SDK 58 still requires it; RNTL ships its own renderer).
   - scripts: add `"test": "jest"`.
   - Install Expo-managed packages with `npx expo install` so versions match SDK 58.
2. **`mobile/.env.example`** — document `EXPO_PUBLIC_API_URL=http://localhost:8000` with a comment that a real phone needs the LAN IP (e.g. `http://192.168.1.5:8000`). Add `.env` to `mobile/.gitignore`.
3. **`src/lib/config.ts`** — `export const API_URL: string = process.env.EXPO_PUBLIC_API_URL ?? 'http://localhost:8000';` plus `export const API_PREFIX = '/api/v1';`. Single source of truth for the base URL.
4. **`src/types/health.ts`** — `export type HealthResponse = { status: 'ok' };` and `export type ConnectionState = 'checking' | 'connected' | 'db_down' | 'unreachable';`.
5. **`src/api/client.ts`** — `export class ApiError extends Error` carrying a `status: number`; `async function apiGet<T>(path: string, opts?: { timeoutMs?: number }): Promise<T>`: builds `${API_URL}${API_PREFIX}${path}`, uses `fetch` with an `AbortController` timeout (default 5000 ms), throws `ApiError(res.status)` on non-2xx (so TanStack Query treats it as an error and the status is inspectable), returns parsed JSON. No auth header yet (F1 adds it).
6. **`src/lib/health.ts`** — pure helper `export function interpretHealth(q: { isPending: boolean; isError: boolean; error?: unknown; data?: HealthResponse }): ConnectionState`: `isPending` → `'checking'`; `data?.status === 'ok'` → `'connected'`; `error instanceof ApiError && error.status === 503` → `'db_down'`; otherwise → `'unreachable'`. Unit-tested (§10). Keeps the mapping out of the screen.
7. **`src/api/use-health.ts`** — `export function useHealth()` → `useQuery({ queryKey: ['health'], queryFn: () => apiGet<HealthResponse>('/health'), retry: false, staleTime: 0 })`. `retry: false` so a down server fails fast.
8. **`src/app/_layout.tsx`** — wrap existing tree in `QueryClientProvider` with a module-level `QueryClient` (default options `{ queries: { retry: false } }`). Keep `ThemeProvider`, splash, `<AppTabs/>`.
9. **Tab screens** (replace demo screens; keep `index` as the first/Dashboard tab):
   - `src/app/index.tsx` → **Dashboard** placeholder (title + "Coming soon").
   - `src/app/tenants.tsx` → **Tenants** placeholder.
   - `src/app/rooms.tsx` → **Rooms** placeholder.
   - `src/app/settings.tsx` → **Settings**: calls `useHealth()`, maps via `interpretHealth`, renders a status pill (Checking… / Connected / Server up, database down / Can't reach server), a **Retry** button (`refetch`), and the resolved `API_URL` as muted debug text. App version from `expo-constants` (optional).
   - **Delete** `src/app/explore.tsx`.
10. **`src/components/screen-placeholder.tsx`** — small reusable `<ScreenPlaceholder title=… />` built on `ThemedView`/`ThemedText` for the three non-Settings tabs (keeps them one line each).
11. **`src/components/status-pill.tsx`** — presentational pill taking `state: ConnectionState`; label + colour per state (checking→"Checking…"/muted, connected→"Connected"/green, db_down→"Server up, database down"/amber, unreachable→"Can't reach server"/red) from the new theme tokens. ## 11. Edge cases and risks
- **`localhost` on a real phone fails** — the device can't reach the laptop's loopback; must use the LAN IP. `.env.example` comment + Settings showing the resolved URL make this debuggable. (CLAUDE.md §11)
- **`fetch` never times out by default** — without an `AbortController` the health query can hang, so "Can't reach server" would never appear. Timeout (~5 s) is mandatory (§6 rule 4).
- **503 vs truly unreachable** — backend up but DB down returns 503, shown as a distinct "Server up, database down" so the owner/developer can tell a server problem from a connectivity problem. Depends on the client surfacing the HTTP status (`ApiError`).
- **`EXPO_PUBLIC_*` requires a Metro restart** — changing `.env` needs `expo start -c` / reload to re-inline the value; note it so the developer isn't surprised by a stale URL.
- **`jest-expo` transform config** — RN/Expo/TanStack ESM packages must be in `transformIgnorePatterns` allowlist or tests fail to parse. Known setup friction; validate `npm test` actually runs.
- **React 19.3 / RN 0.88 / React Compiler are very new** — `react-test-renderer` and `@testing-library/react-native` versions must match React 19.3; pin carefully. The required render test is deliberately trivial to limit exposure.
- **NativeTabs route names** — each `NativeTabs.Trigger name=` must match a file in `src/app/`; a typo yields a blank tab. Keep `index` as the first tab to avoid an extra redirect.
- **Mixed-content / cleartext HTTP** — dev uses `http://` over LAN; fine in Expo Go dev. A production HTTPS URL is a later (hosting) concern.
- **Self-signed / firewall** — laptop firewall may block the phone; binding uvicorn to `0.0.0.0` and allowing the port is part of the manual steps.
